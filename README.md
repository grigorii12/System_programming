# System_programming

## Лабораторная работа №1

Прозоров Григорий Дмитриевич. Рабочее окружение и командная строка Linux.

Работа выполнена и проверена в GitHub Codespaces, окружение `organic couscous`. Установлены gcc, gdb, fasm, mc и поддержка сборки C для 32-разрядной Linux.

### Результаты

- `Lab_1/sandbox/Прозоров.asm` и `Прозоров` — исходник FASM и исполняемый ELF32.
- `Lab_1/sandbox/C_version.c` и `C_version` — программа C и исполняемый ELF32.
- `Lab_1/sandbox/Disassemble` — вывод GDB: весь код FASM, функции main и _start программы C.
- `Lab_1/sandbox/Build_commands`, `Build_trace.txt`, `Build_output.txt` — команды сборки, фактический журнал и результаты.
- `Lab_1/Work_files` — команды всех 12 пунктов работы с файлами, с комментариями.
- `Lab_1/sandbox/Work_trace.txt`, `Work_output.txt` — фактическое выполнение команд и проверка прав.
- `Lab_1/Work` — тексты, результаты, gzip-файлы и tar-архив `MyAchiv`.

Обе программы выводят:

```text
Прозоров
Григорий
Дмитриевич
```

Проверены совпадение вывода обеих программ с ожидаемым текстом, формат ELF 32-bit Intel 80386, содержимое скопированных файлов, обратный порядок строк, последняя строка Text #3, целостность gzip и содержимое tar.

### Пояснения к условию

1. В пункте 1 названа «Лабораторная работа №1!», а в пункте 2 — «Контрольная работа №1!». Созданы обе папки с правами 772 (rwxrwx-w-).
2. Папка «ФИО» получила права 200 (d-w-------). Для операций внутри неё временно добавлены r и x, после работы восстановлены 200. Эти действия отражены в журнале. Имена папок «ФИО» оставлены буквально как в задании.
3. Использовано `gzip -k`: исходные тексты нужны в следующих пунктах. Архив содержит сжатые файлы на момент пункта 7; Text #3 тогда ещё пуст.
4. «В обратном порядке» трактуется как обратный порядок строк (`tac`). В Result_3 записано содержимое файлов на T, затем реальное ядро Codespace и дата выполнения в UTC.
5. Git не сохраняет права каталогов и пустые папки. Для пустой папки добавлен .gitkeep. После клонирования восстановить права можно так:

```bash
chmod 772 "Lab_1/Work/Контрольная работа №1!" "Lab_1/Work/Лабораторная работа №1!"
chmod 200 "Lab_1/Work/ФИО"
```

Для просмотра файлов внутри ФИО или выполнения `git add` временно требуется `chmod u+rx "Lab_1/Work/ФИО"`, затем снова `chmod 200 "Lab_1/Work/ФИО"`.

### Повторная проверка

```bash
./Lab_1/sandbox/Прозоров
./Lab_1/sandbox/C_version
cat Lab_1/sandbox/Disassemble
```

Чтобы повторить все действия без перезаписи результата, из корня репозитория:

```bash
script="$PWD/run_lab_1.sh"
trial=$(mktemp -d)
(cd "$trial" && bash "$script")
```

Файл `.devcontainer/devcontainer.json` устанавливает нужные пакеты при создании нового Codespace.
